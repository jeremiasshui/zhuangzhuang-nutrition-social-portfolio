# RUNBOOK｜實際工作流程

## 0. 每週先做 Research Radar

```text
/research-radar
目標：規劃下週內容。
範圍：減重、外食、聚餐、復胖、生活情境。
輸出：
- 受眾最近在問什麼
- 受眾原句／常見誤解
- 競品／創作者案例
- 平台趨勢（只當訊號，不當策略）
- 可做題目 15–20 個
- 每題來源與風險
```

## 1. 從 15–20 題選成 9 支

```text
/plan-9-videos
依本週 research radar 產生 9 支 content board。
要求每支標示：Audience、Tension、Goal、Hook angle、Key claim、CTA、Funnel role、Platform priority、Risk。
避免 9 支都是同一種知識型內容。
```

內容組合至少涵蓋：
- Reach：生活痛點／反直覺／高辨識情境。
- Trust：營養觀念／判斷方法／案例拆解。
- Action：可以今天做的小步驟。
- Conversion：自然承接 LINE／諮詢／產品，但不可每支硬導流。

## 2. 寫單支可拍攝腳本

```text
/write-script
使用 content board 的 S3。
長度 35–60 秒。
需要：Hook、spoken script、beat-by-beat、on-screen text、fact note、CTA、production note。
先做到資訊正確與口語自然，不要替剪輯師設計複雜特效。
```

## 3. 跨平台轉譯

```text
/repurpose-content
以 S3 核心觀點為準，製作：
IG/Reels caption、Threads、Facebook、小紅書圖文結構、YouTube Shorts title/description。
每個平台說明「為什麼這樣改」。
```

## 4. 拍攝／剪輯交接

```text
/handoff-qa
把 S3 轉成 production handoff：
- 不能改掉的核心觀點
- 必須保留的 claim / wording
- 可以自由發揮的部分
- B-roll / 素材需求
- 字幕重點
- CTA
- 高風險資訊
```

剪輯完成後再次執行 `/handoff-qa`，比較 final cut / subtitle transcript 與 approved script。

## 5. 成效回顧

將平台數據放入 `data/performance.csv`，再：

```text
/review-performance
不要只排行觀看數。
請按 platform、topic、hook、audience、format、CTA 比較，標註樣本數與限制。
最後只提出 3 個下一輪可測試假設。
```

## 6. 主管與營養師回饋

```text
/learn-feedback
輸入主管或營養師的修改與原因。
區分：
- 單篇偏好
- 平台規則
- 品牌語氣規則
- 營養事實修正
- 製作流程規則
只有重複且穩定的回饋才能提議升級到 core memory。
```
