# Memory Design｜為社群企劃而設計

## Layer A｜Core memory：穩定但仍可版本控管

- `00-brand-core.md`：品牌使命、服務原則、禁區。
- `01-role-and-success.md`：職務目標與成功條件。
- `02-audience.md`：Persona/JTBD，不放短期熱門留言。
- `03-content-strategy.md`：內容支柱、漏斗角色、CTA 原則。
- `04-platforms.md`：各平台內容邏輯。
- `05-claims-and-risk.md`：營養與健康資訊治理。
- `06-production-quality.md`：交接與驗收標準。

## Layer B｜Project knowledge：可變但跨週可重用

- `source-registry.md`：官方／研究／品牌來源。
- `claim-ledger.md`：可發布的事實狀態。
- `feedback-ledger.md`：主管／營養師回饋及原因。
- `audience-language-bank.md`：真實留言、FAQ、用語模式。
- `reference-case-library.md`：參考案例，不等同照抄。
- `hook-pattern-library.md`：Hook 類型＋使用情境。

## Layer C｜Working memory：本週工作

- current-week.md
- research-radar.md
- 9-video-board.md
- current-brief.md
- handoff-status.md
- decision-log.md

每週結束後歸檔，不直接變品牌真理。

## Layer D｜Learning memory：由成果逐步驗證

- performance.csv
- experiment-log.md
- validated-learnings.md
- failed-patterns.md

## Layer E｜Agent memory

各 subagent 只記與自己角色相關的「工作方式改進」。不可把未驗證品牌事實寫入 agent memory。

## 升級規則

Working → Project：跨至少 2 個週期仍有用，或主管明確確認。
Learning → Project：有足夠樣本且能描述適用條件。
Project → Core：品牌方／主管確認為穩定規則，且不是單篇特例。
