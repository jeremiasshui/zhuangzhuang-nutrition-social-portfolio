# 社群內容代理迴圈

一個有界的多代理系統：寫手產出壯壯營養師的跨平台文案，程式檢查與五種審稿員驗證，總編裁決，人做最後決定。這份名詞表是所有代理、文件與對話的共同語言。

## 內容

**腳本**：
規劃書裡的一支短影音主題，含開場、主體、重點整理、行動引導四段，編號 S1 到 S9。
_Avoid_：題目、貼文、影片

**文案**：
一支腳本在一個平台上的成品，一個檔案。九支腳本乘四個平台共 36 份。
_Avoid_：貼文、內容、稿子

**平台**：
文案的目的地，只有四個：shorts、threads、fb、xhs。
_Avoid_：頻道、管道

**品牌鐵則**：
所有文案必須遵守的語氣規則與三條硬性守門，唯一來源是 `brief/brand-rules.md`。
_Avoid_：風格指南、tone

**硬性守門**：
三條一出現就不通過的規則：保證結果、熱量數字、產品推薦。CI 與審稿員都擋。
_Avoid_：黑名單、禁語

**待確認標注**：
文案裡標記「這句還沒被驗證」的括號，有三種：【待營養師確認】【待團隊確認】【授權待確認】。系統靠它記住未驗證的事。
_Avoid_：註解、備註

**人物**：
一個具體的受眾模擬對象，有職業、減肥史、當週處境、用語、平台習慣。寫手對著人物寫，受眾審稿員讓人物讀。唯一來源是 `brief/personas.md`。
_Avoid_：persona、受眾輪廓、TA

**結構範本**：
從同業高瀏覽貼文抽出的開場與段落結構，只借結構不借內容。唯一來源是 `brief/competitors.md`。
_Avoid_：範例、爆款、模板

## 角色

**寫手**：
負責一個平台、產出該平台九份文案的代理。只讀簡報包與審稿檔，只寫自己平台的文案。
_Avoid_：作者、生成器

**審稿員**：
對文案下判定、從不改寫文案的代理。五種：品牌語氣、營養標注、官方資料查證、廣告法規、受眾模擬。
_Avoid_：審查員、檢查員、reviewer agent

**總編**：
主對話。只做派工、裁決、寫討論記錄三件事。
_Avoid_：協調者、orchestrator、主代理

**人**：
迴圈的出口。看未收斂清單、決定合併與否、抽查判定、拿不到的授權由人去要。
_Avoid_：使用者、operator

## 驗證

**文案審稿**：
審稿員依驗收清單對文案下判定的過程。
_Avoid_：審查、review

**程式審查**：
對 harness 本身（代理定義、檢查程式、文件）在 PR 裡的審查。
_Avoid_：審稿、code review

**驗收清單**：
九條可判定的條件 C1 到 C9，唯一來源是 `brief/acceptance-checklist.md`。每條指定由哪個審稿員判。
_Avoid_：規則、標準、rubric

**判定**：
審稿員對一份文案的一條驗收條件給的結果，只有 PASS 或 FIX。FIX 必附原句與改法。
_Avoid_：分數、評價、意見

**CI 檢查**：
程式能確定判斷的五項檢查，在 PR 上自動跑：檔案數、檔頭格式、硬性守門、字數上限、單一行動引導。
_Avoid_：測試、lint

**裁決**：
兩位審稿員對同一句意見矛盾時，總編的決定。必寫進討論記錄。
_Avoid_：仲裁、覆核

**黃金樣本**：
答案由人先定好的一小批文案，用來考審稿員抓不抓得到。
_Avoid_：測試集、eval set

**推翻率**：
人抽查判定後，不同意審稿員的比率。驗證器成熟與否的唯一總指標。
_Avoid_：準確率、錯誤率

## 迴圈

**回合**：
一次「寫手產出 → CI 檢查 → 審稿員判定 → 統計 FIX」的完整循環。以 git 歷史記錄，不另建資料夾。
_Avoid_：iteration、輪

**迴圈**：
回合的重複，最多三回合。
_Avoid_：loop、pipeline

**收斂**：
一個平台的九份文案 CI 全綠且九條驗收全 PASS 的狀態。收斂才合併。
_Avoid_：完成、通過

**未收斂**：
三回合後仍有 FIX 的狀態。不合併，總編列清單交給人。
_Avoid_：失敗、逾時

**升級**：
一條反覆出現的 FIX 模式被寫成 CI 檢查並附測試的過程，經 PR 由人核准。系統唯一的自我改進機制。
_Avoid_：自動化、優化

**討論記錄**：
`log/discussion.md`，每回合的 FIX 統計、代表性意見與改法、裁決、指標、未收斂清單。作業要附的「AI 討論過程」就是它。
_Avoid_：日誌、log、對話紀錄
